# ✅ Функция разблокировки специалиста - РЕАЛИЗОВАНА

## Что было сделано

### Задача
Реализовать логику, при которой специалист получает доступ к чату только после того, как клиент отправит ПЕРВОЕ сообщение.

### Решение

#### 1️⃣ Backend API (Node.js/Express)

**Файл**: `backend/src/routes/messages.js`

✅ **POST /api/messages** - Отправка сообщения
- При сохранении сообщения проверяет:
  - Первое ли это сообщение? (`messageCount === 1`)
  - Отправитель - клиент? (`req.user.role === 'user'`)
  - Переписка еще не разблокирована? (`!specialistUnlocked`)
- Если все условия верны:
  - Устанавливает `conversation.specialistUnlocked = true`
  - Отправляет socket.io событие `unlock_chat` специалисту

✅ **GET /api/messages/:conversationId** - Загрузка сообщений
- Проверяет доступ:
  - Если пользователь - специалист и `specialistUnlocked === false`
  - Возвращает ошибку 403 "Доступ еще не открыт"
  - Клиенты всегда могут смотреть сообщения

#### 2️⃣ Frontend UI (React Native)

**Файл**: `components/ChatScreen.js`

✅ **Состояние**
- Добавлен state `accessDenied` для отслеживания статуса доступа

✅ **Логика загрузки**
- `loadMessages()` теперь обрабатывает ошибку 403
- Если ошибка доступа - устанавливает `accessDenied = true`

✅ **Socket.io слушатель**
- Слушает событие `unlock_chat` от backend
- При получении события:
  - Убирает блокировку (`setAccessDenied(false)`)
  - Перезагружает сообщения (`loadMessages()`)

✅ **UI Блокировка**
- Показывает экран с:
  - 🔒 Иконкой замка
  - "Доступ закрыт"
  - "Вы сможете просмотреть переписку после того, как клиент отправит первое сообщение"

#### 3️⃣ База данных (MongoDB)

**Файл**: `backend/src/models/Conversation.js`

✅ Поле `specialistUnlocked: Boolean` (default: false)
- Отслеживает статус разблокировки

## Сценарий использования

```
1. Клиент отправляет заявку
2. Специалист видит заявку и отправляет ответ
3. Клиент открывает чат со специалистом
4. Специалист открывает тот же чат
   └─ Видит: [🔒 Доступ закрыт]
5. Клиент пишет ПЕРВОЕ сообщение
   └─ Backend: specialistUnlocked = true
   └─ Backend: отправляет unlock_chat через socket.io
6. Специалист получает сообщение об разблокировке
   └─ UI обновляется автоматически
   └─ Видит: [все сообщения]
7. Обе стороны могут переписываться
```
