# Тестирование функции разблокировки специалиста (Specialist Unlock)

## Описание функции
После того, как клиент отправит ПЕРВОЕ сообщение в чат, специалист автоматически получает доступ к переписке. До этого момента специалист видит сообщение "Доступ закрыт".

## Архитектура

### Backend (Node.js)
- **Endpoint**: `POST /api/messages`
  - Создает сообщение в БД
  - Проверяет: первое ли это сообщение от клиента (`messageCount === 1`)
  - Если да и `specialistUnlocked === false`, устанавливает `specialistUnlocked = true`
  - Отправляет socket.io событие `unlock_chat` специалисту через комнату `user_{specialistId}`

- **Endpoint**: `GET /api/messages/:conversationId`
  - Проверяет: если пользователь - специалист (`req.user.role === 'specialist'`) и `specialistUnlocked === false`
  - Если да, возвращает ошибку 403 с сообщением об ограничении доступа

### Frontend (React Native)
- **ChatScreen.js**:
  - Состояние: `accessDenied` (true/false)
  - При загрузке сообщений: если ошибка 403, устанавливает `accessDenied = true`
  - Показывает UI блокировку с иконкой замка
  - Слушает socket.io событие `unlock_chat`
  - При получении события: `setAccessDenied(false)` и перезагружает сообщения

### Database Model (MongoDB)
- **Conversation**:
  ```javascript
  specialistUnlocked: { type: Boolean, default: false }
  ```

## Тестовый сценарий

### Шаг 1: Подготовка
1. Убедитесь, что backend работает: `npm run dev` в папке `backend/`
2. Убедитесь, что frontend работает: `npm start` в корне проекта
3. Оба сервера должны быть готовы

### Шаг 2: Создание заявки (как клиент)
1. Откройте приложение с ролью "клиент" (user)
2. Перейдите в AppsScreen → AddScreen
3. Создайте новую заявку:
   - Title: "Тестовая заявка"
   - Budget: 1000
   - Work Mode: "online"
   - Categories: выберите одну
4. Заявка должна быть видна в AvailableApplicationsScreen с статусом "open"

### Шаг 3: Отправка ответа (как специалист)
1. Откройте второе устройство/браузер с ролью "специалист"
2. Перейдите в AvailableApplicationsScreen (должна быть видна заявка из шага 2)
3. Нажмите "Отправить предложение"
4. Вернитесь на клиента, откройте ResponsesViewScreen
5. Должна быть видна карточка с предложением специалиста
6. Нажмите кнопку "Чат"

### Шаг 4: КЛЮЧЕВОЙ МОМЕНТ - Первое сообщение клиента
1. В ChatScreen (клиент) напишите первое сообщение (например, "Привет!")
2. Нажмите отправить
3. **Важно**: Обратите внимание на что происходит:
   - Backend должен:
     - Сохранить сообщение
     - Проверить: `messageCount === 1` и `req.user.role === 'user'` → TRUE
     - Установить `conversation.specialistUnlocked = true` в БД
     - Отправить socket.io событие `unlock_chat` специалисту
   
### Шаг 5: Проверка разблокировки специалиста
1. На специалисте откройте ChatScreen
2. **До этого момента** он должен был видеть:
   ```
   [Lock Icon]
   Доступ закрыт
   Вы сможете просмотреть переписку после того, как 
   клиент отправит первое сообщение.
   ```

3. **После отправки первого сообщения клиентом** специалист должен:
   - Получить socket.io событие `unlock_chat`
   - Автоматически переключиться из режима "заблокирован" в режим "открыт"
   - Увидеть все сообщения (в т.ч. первое сообщение клиента)

### Шаг 6: Двусторонняя переписка
1. Специалист может теперь ответить на сообщение
2. Клиент получит сообщение в реальном времени через socket.io
3. Оба могут переписываться дальше

## Ожидаемые результаты

✅ **Успешный результат**:
- Специалист изначально видит "Доступ закрыт"
- После первого сообщения клиента специалист видит сообщение
- Оба пользователя могут переписываться
- Нет ошибок в консоли

❌ **Возможные проблемы**:
1. **Специалист не видит разблокировку**: 
   - Проверьте socket.io соединение
   - Проверьте, что `io.to('user_' + to.toString())` отправляет в правильную комнату
   - Проверьте, что frontend слушает событие `unlock_chat`

2. **Ошибка "Доступ запрещен" не исчезает**:
   - Проверьте, что `loadMessages()` перезагружается после события `unlock_chat`
   - Проверьте, что `specialistUnlocked` обновляется в БД

3. **Двойные сообщения**:
   - Убедитесь, что отправка идет ТОЛЬКО через REST API, не через socket.emit

## Метрики логирования
Откройте консоль браузера и backend логи:

**Backend логи**:
- `Socket ${socket.id} joined room user_${userId}` - специалист подключился
- `Chat unlocked: ...` - сообщение об разблокировке отправлено

**Frontend логи**:
- `Chat unlocked: ...` - специалист получил событие разблокировки
- Message отправлена через REST API (успех 201)
